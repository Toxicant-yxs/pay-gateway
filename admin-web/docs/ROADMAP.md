## 3. 技术债务清理计划

| 技术债务 | 计划版本 | 处理方式 |
|----------|----------|----------|
| Mock数据硬编码在组件中 | v1.0 | 抽取为独立的Mock层，切换为API调用 |
| 缺少API层封装 | v1.0 | 创建`src/api/`目录，按模块封装接口 |
| 缺少错误边界处理 | v1.0 | 添加全局错误处理和ErrorBoundary |
| 缺少权限控制 | v1.0 | 实现RBAC和权限指令 |
| Vite配置较简单 | v1.0 | 添加路径别名、代理配置、构建优化 |
| 缺少单元测试 | v1.0+ | 逐步添加Vitest测试用例 |
| 图表数据无真实更新机制 | v1.5 | 引入WebSocket实时推送 |
| 样式未完全主题化 | v2.0 | CSS变量体系完善，支持主题切换 |

## 4. 风险与缓解

| 风险 | 阶段 | 影响 | 缓解措施 |
|------|------|------|----------|
| 后端API延期交付 | Phase 2 | 高 | 先使用Mock Server联调，API就绪后切换 |
| 支付通道对接复杂 | Phase 3 | 高 | 优先对接1-2个主力通道，其他逐步扩展 |
| 性能不达预期 | Phase 2 | 中 | 提前进行压力测试，识别瓶颈优化 |
| 安全合规审计 | Phase 2 | 高 | 提前引入安全审计，遵循PCI-DSS规范 |
| 需求变更频繁 | 全阶段 | 中 | 采用敏捷迭代，每两周一个Sprint，需求评审锁定范围 |

---

## 5. 版本发布节奏

- **MVP/原型阶段**：按需快速迭代
- **v1.0 开发阶段**：每2周一个Sprint，每个Sprint末进行演示
- **上线后维护**：
  - 补丁版本（x.x.x）：Bug修复，按需发布
  - 小版本（x.x.0）：功能新增，每月一个版本
  - 大版本（x.0.0）：重大功能，每季度一个版本
